Qodo finding 2 (Medium, Reliability), PR #1. Review: https://github.com/jlevy/paraverse/pull/1#pullrequestreview-5639982758. Comment: https://github.com/jlevy/paraverse/pull/1#discussion_r4368485576

Files: `.claude/settings.json:8-30` and `.codex/hooks.json:8-30` (SessionStart and PreCompact entries).

Problem: the SessionStart and PreCompact commands are relative (`bash .claude/scripts/tbd-session.sh`, `bash .codex/tbd-session.sh`, `bash .claude/scripts/ensure-gh-cli.sh`, `bash .codex/ensure-gh-cli.sh`). Both hosts run hook commands in the session's current directory: Codex docs say "Commands run with the session `cwd` as their working directory" and recommend resolving from the git root; Claude Code docs say handlers "run in the current directory", which follows `cd`. A session started in, or moved to, a subdirectory cannot open the scripts. The generated Claude PostToolUse entry already uses `"$CLAUDE_PROJECT_DIR"`, so the other entries are inconsistent with it.

Verified: from the `.tbd/` subdirectory, `bash .claude/scripts/tbd-session.sh --brief` and `bash .codex/tbd-session.sh --brief` both fail with "No such file or directory", exit 127.

Disposition: deferred. Re-running `tbd setup --auto` on a scratch copy whose `.codex/hooks.json` used `$(git rev-parse --show-toplevel)` re-added the generated relative entry beside the edited one, so a local fix would leave a failing duplicate. Upstream fix: generate `"$CLAUDE_PROJECT_DIR"/...` for Claude Code and a git-root-resolved path for Codex in every hook entry. Waits on a tbd release with the fix, then `tbd setup --auto` here.
