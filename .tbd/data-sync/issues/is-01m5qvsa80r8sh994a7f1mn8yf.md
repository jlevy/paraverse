Qodo finding 4 (Medium, Reliability), PR #1. Review: https://github.com/jlevy/paraverse/pull/1#pullrequestreview-5639982758. Comment: https://github.com/jlevy/paraverse/pull/1#discussion_r4368485583

Files: `.claude/hooks/tbd-closing-reminder.sh:27-31` and `.codex/tbd-closing-reminder.sh:27-31`.

Problem: the hook reads `tool_input.command` with `jq` and neither checks for jq nor falls back to another parser. Without jq, the command is empty, the push check never matches, and the hook exits 0 with only a stderr line. Claude Code never passes stderr to the model when a hook exits 0, and Codex documents no use for it on exit 0.

Verified: with a PATH holding cat, git, tbd and node but no jq, piping `{"tool_input":{"command":"git push origin setup/tbd"}}` into the hook printed nothing on stdout, wrote `line 28: jq: command not found` to stderr, and exited 0. The same input with jq on PATH printed the 38-line closing checklist.

Disposition: deferred. Re-running `tbd setup --auto` on a scratch copy reverted a local edit to this script. Upstream fix: check for jq and fall back (for example to node, which tbd already needs, or a `grep` match on the raw payload), and report a visible error when the payload cannot be parsed. Waits on a tbd release with the fix, then `tbd setup --auto` here.
