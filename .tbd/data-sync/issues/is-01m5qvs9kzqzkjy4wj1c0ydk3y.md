Files: `.claude/scripts/ensure-gh-cli.sh:178,184,243,284` and the same lines in `.codex/ensure-gh-cli.sh`.

Problem: the pinned gh download at :178 runs `curl -fsSL` with no `--connect-timeout` or `--max-time`, and the NO_PROXY retry at :184 sets only `--connect-timeout 15`. The first `gh auth status` checks at :243 and :284 are not wrapped in `run_bounded`, although the proxy retry at :254 is. The stacked-PR download in the same script (:500, :504) already uses `--connect-timeout 15 --max-time 120`. If GitHub or a proxy stops responding, the SessionStart hook can use its whole 120-second timeout before the agent proceeds.

Verified by reading the lines above at head 48f560c; the hook's `timeout: 120` caps the stall, so the effect is a slow start, not a hang.

Disposition: deferred. The script is generated by `tbd setup`. Upstream fix: add `--connect-timeout` and `--max-time` to both gh downloads and wrap the initial `gh auth status` calls in `run_bounded`. Related upstream issue: jlevy/tbd#195 (make ensure-gh-cli.sh refresh on upgrade). Waits on a tbd release with the fix, then `tbd setup --auto` here.
